# Assignment Key Points

Distilled from `assignment.md`. Read this first; open the full brief for detail.

## What reviewers judge

- Product judgment as much as code: deliberate scope cuts, explained clearly
- Depth in a few areas beats shallow coverage everywhere
- Full stack: UI, server logic, persistence, access control
- Editing experience feels usable and coherent
- Code clarity and delivery discipline
- Practical AI use without giving up engineering standards

## Hard constraints

- Time box: 4-6 hours. At the limit, stop and submit what exists
- Reviewers must not need to pay for anything (free tier hosting and database only)
- Live URL must work with seeded accounts so sharing can be tested
- Supported upload types must be stated in the UI and the README
- A partial feature must be declared: what works, what is incomplete, what comes next in 2-4 hours

## Core scope checklist

- [ ] Create, rename, edit, save, reopen documents
- [ ] Bold, italic, underline, headings, bulleted and numbered lists
- [ ] File upload that becomes an editable document
- [ ] Owner, share with another user, owned vs shared visible
- [ ] Persistence across refresh with formatting intact
- [ ] Validation and error handling
- [ ] At least one meaningful automated test
- [ ] Deployed and reachable

## Deliverables (one Google Drive folder)

- Source code
- `README.md` with local setup and run steps
- Architecture note (what was prioritized and why)
- AI workflow note: tools used, where AI sped things up, what was changed or rejected, how it was verified
- `SUBMISSION.md` listing exactly what is included
- Live URL and review credentials
- Text file with the walkthrough video URL
- Screenshots or demo GIF if setup is non-trivial

## Walkthrough video (3-5 min, unlisted Loom/YouTube)

Main flow, what works end to end, what was cut on purpose, key decisions, how AI helped.

## Stretch (optional, only after core works)

Collaboration indicators, comments, version history, export to PDF/Markdown, richer roles. Cheapest: export to Markdown. Roles (editor/viewer) are already in the access model.
